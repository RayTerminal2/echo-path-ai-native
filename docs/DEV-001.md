# DEV-001｜方向回声 V0.2 工程化

**状态：待 Codex 开发**  
**优先级：P0**  
**产品性质：玩法候选 / 尚未定稿**  
**建议开发策略：保守重构，功能保持不变**

## 背景 / 问题
当前 V0.2 在 `index.html` 中包含 HTML、CSS、关卡数据、规则逻辑、渲染和统计。虽然已有 9 个验证过的关卡，但后续修改难以审查和单测。

## 目标
在**不更改游戏玩法、关卡内容和外观行为**的前提下，建立易于维护、可测试的纯前端代码结构，为机制压力测试提供稳定基础。

## 任务范围
1. 从 `index.html` 抽离游戏规则为 `src/game-engine.mjs`，提供明确的纯函数或可预测状态转换。
2. 使用 `data/levels.v0.2.json` 作为唯一的关卡数据源，移除 HTML 内硬编码的重复关卡数据。
3. 将 UI 事件、渲染与规则计算分离，保留现有视觉布局及交互功能。
4. 使用 Node 内置 `node:test` 测试规则；要求覆盖：写入箭头、合法移动、墙/边界、旧箭头限制、收集、提前通过出口、最终胜利、撤销、重开、九关参考路径。
5. 保留复制试玩记录及关键统计字段（撤销、重开、无效操作、通关步数）。
6. 更新 README 中的启动、测试、目录说明；交付变更清单和已知风险。

## 非目标
- 不扩张到 50 关、不加新道具、不改关卡难度、不改美术风格。
- 不部署服务器、不加登录、不引入数据库或付费服务。
- 不把自动化可解性冒充真实用户体验。

## 验收条件（PM 检查）
- AC1：九关数据逐字段与 `data/levels.v0.2.json` 一致。
- AC2：九条参考路径全部能在**重构后的实际游戏规则模块**上完成，并达到原记录步数：5/11/16/14/13/17/19/19/23。
- AC3：旧箭头方向限制不可绕过，移动失败不改变游戏状态。
- AC4：通关后的撤销有效、重开归零，统计/复制记录仍可用。
- AC5：桌面和移动端仍可操作，没有明显布局溢出或 JS 异常。
- AC6：`npm test` 无失败；README 给出可复现命令。
- AC7：原版基线 `legacy/echo-v0.2-original.html` 未修改。

## 交付物
- Codex 的代码改动 / 分支或 PR
- 测试文件和 `npm test` 输出
- 一份简短的开发说明：变更、测试结果、风险、需要 PM 决策的问题
