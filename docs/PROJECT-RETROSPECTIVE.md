# 《方向回声》项目复盘（ECHO-CLOSE）

**结项日期**：2026-10-24

**结项范围**：停止《方向回声》的主动功能开发，归档 50 关 H5 版本、自动化测试、静态发布包与实验记录。

**结论性质**：本文区分「实际验证结果」「真实主观反馈」「产品分析」三类信息。除特别说明外，本文不包含外部用户数量、留存率、完成率或第三方测试结论。

---

## 一、项目背景与目标

《方向回声》最初来自一个单文件 H5 玩法原型（V0.2，九关）。核心规则是：

- 角色在上下左右相邻的非墙格子间移动；
- 首次离开一个格子时，该格永久记录离开方向；
- 再次进入已记录方向的格子时，只能按记录方向离开；
- 收集全部 ★ 并最终停在 E 通关。

项目目标不是直接量产参赛作品，而是验证这套「历史方向约束」能否支撑有持续吸引力的解谜体验。后续目标依次调整为：

1. 工程化规则与关卡数据，保留九关基线；
2. 设计对照实验关卡，验证「旧路重访」「收集顺序」「多路口取舍」等策略；
3. 在获得有限正面反馈后，扩展为五章 50 关的完整 H5 候选作品；
4. 增加步数挑战与个人最佳，作为重复游玩的额外动力；
5. 构建可公开分享的静态发布包。

50 关、测试与发布包均已完成，但产品负责人经过实际体验后判断核心玩法吸引力不足，决定停止主动开发，转向新的游戏创意。本复盘记录这一判断及其依据。

## 二、核心玩法假设

项目期间实际检验过的假设包括：

| 编号 | 假设 | 验证方式 | 结果性质 |
|---|---|---|---|
| H1 | 历史方向箭头能形成可感知的路线规划与回访决策 | V0.2 试玩、实验关卡求解与试玩 | 部分成立；大量路线无需回访 |
| H2 | 收集顺序可以制造「先远后近」等策略取舍 | B1、B1+、E1、E2 与求解器穷举 | 个别关卡有效，整体未稳定复现 |
| H3 | 多路口与出口规划能增加决策密度 | A/C 类实验关卡 | 未获得明确正面体验证据 |
| H4 | 增加关卡数量与步数目标能延长游玩动力 | 50 关交付 + 步数挑战 | 步数挑战获单人正面反馈；50 关趣味性未验收 |
| H5 | 旧路约束会成为通关必经机制 | 关卡穷举与历史分支审计 | **不成立**：存在大量可绕开的通关路线 |

其中 H5 的失败是最终产品判断的关键技术原因。

## 三、关键设计实验与真实反馈

### 3.1 实验关卡（DEV-002 至 DEV-005-B）

实际制作并接入 `?mode=experiment` 的实验关卡包括：

- A/B/C 三关：旧路重访、顺序陷阱、多路口规划；
- B1「先远后近」、B2「预留退路」；
- B1+「先远后近·进阶」；
- E1「诱人的近路」、E2「取舍的时机」。

对应的真实反馈（均为产品负责人本人的单次或少量体验，不是外部用户样本）：

- **PT-002**：认为 B「顺序的陷阱」方向值得继续探索；不希望棋盘直接提示可移动位置；指出部分格子变形。
- **PT-003**：B 较简单；B1 产生了实际思考乐趣，玩家需要推翻「先拿最近收集物」的直觉；B2 有设计巧思，但按自然路线即可通关，未明显感到「预留退路」的必要；角色遮挡箭头。
- **PT-004**：B1+ 未经策略思考直接通关，且全程没有重复进入任何格子。随后的机制审计确认 B1/B1+ 都存在无重复通关路线，箭头规则对通关并非必要。
- **PT-005**：E1 有趣，存在主动思考和收集顺序策略；E2 有思考但整体乐趣一般，首次 20 步通关后因 16 步目标产生优化欲望；综合评价为「整体仍不够好」。
- **PT-006**：首批十关中 C2-02、C4-02、C5-02 体验与此前关卡相近，未表现出明显创新；玩家认为创新空间可能受核心规则限制；同时明确认为步数挑战有助于提高挑战性和提前规划意识。

这些反馈支持了一个逐步清晰的判断：局部关卡可以制造思考，但核心机制没有稳定转化为持续乐趣。

### 3.2 50 关与步数挑战（DEV-006-B 至 DEV-008-RELEASE）

- 正式战役共 50 关，五章各 10 关；首批 10 关（含 7 关声明式复用与 3 关新设计）加 40 关按槽位生成。
- UI 提供章节标签页、每章通关计数、当前步数、求解器最优步数、个人最佳（localStorage，仅通关后刷新）。
- 步数挑战获得 PT-006 的正面主观反馈，但没有量化试玩、留存或完成率数据。

## 五、最终产品失败判断

产品负责人在实际体验 50 关后，判断核心玩法缺乏足够吸引力，决定停止该游戏的主动开发。这是**产品负责人的主观产品判断**，不是大规模用户测试结论。

支持该判断的真实反馈包括：

- V0.2 阶段已观察到「总体策略趋向尽量绕圈，并可以把出口规划进回环」；
- B2、B1+ 等精心设计的约束没有转化为玩家可感知的决策压力；
- 首批十关的新关卡被认为「与此前关卡相近」，创新空间受核心规则限制；
- E2 等关卡虽有思考，但整体乐趣一般；
- 步数挑战是少数获得明确正面反馈的设计，但它属于附加目标，未能改变核心解谜体验。

需要明确：没有证据表明该游戏对广泛用户无效；能够成立的结论只是「在现有单人体检式体验中，未能证明其具备足够吸引力，因此不值得继续投入主动开发」。

## 六、核心失败原因：历史箭头只在回访时生效

这是本项目的关键技术结论，也是最值得记录的设计教训。

### 6.1 机制本身允许绕开

箭头只在「离开某格后再次进入该格」时才限制移动。如果一条通关路线从不重复进入任何格子，那么箭头规则对这条路线的每一个决策都没有直接影响。

对 50 关正式数据的实际检查结果：

- **35/50 关存在至少一条不重复进入任何格子的通关路线**（关卡 `evidence.simplePath === true`）。这些路线完全绕开历史箭头约束。
- **27/50 关的参考最优路线回访次数为 0**；全部参考路线合计仅 62 次回访进入。
- 使用同一规则引擎做「清除历史箭头后」的完整 BFS：**24/50 关最优步数不变**；另 26 关最优步数下降（例如 C5-07 从 23 降至 13，C2-01 从 16 降至 8）。

这说明箭头规则在相当一部分关卡中不是通关必要条件，甚至不是最优路线的一部分。关卡可以「看起来是方向回声」，实际却按普通走格子解谜完成。

### 6.2 设计意图与实际决策脱节

B1+ 是典型案例：技术上只有 6/24 种收集顺序可通关，但玩家的自然走廊路线本身就是一个合法顺序，且全程无需回访。求解器证明的「顺序约束」因此没有转化为玩家必须做出的取舍。

类似地，B2 的「预留退路」和 E2 的额外箭头陷阱，都可能被自然路线绕过。自动化能证明「存在约束」，不能证明「约束会被感知」。

### 6.3 结论

核心机制的问题不是「没有深度」，而是**深度依赖回访，而回访可以被大量合法路线规避**。当关卡设计者试图提高难度时，容易转向增加收集物、墙体和绕路，而不是让箭头约束成为真正的决策核心；后者又会与「最短步数」目标产生冲突。

## 七、步数优化与减少回访的潜在矛盾

步数挑战是项目中反馈最正面的附加系统，但它与核心机制存在结构性张力：

1. 箭头要产生影响，玩家必须回访旧格；回访通常意味着额外步数。
2. 步数挑战奖励更短路线；更短路线往往是不回访的简单路径。
3. 因此，认真追求最优步数的玩家，反而可能更系统地绕开核心机制。
4. 若为了强制回访而设计更绕的地图，又会让「最优解」显得不自然，并增加玩家对繁琐路线的疲劳。

50 关数据与这一分析一致：27/50 关的参考最优路线完全不回访，35/50 关存在无重复通关路线。该矛盾不是通过增加关卡数量可以自动解决的。

需要强调：这是基于关卡结构与规则的分析，不是经过对照实验验证的玩家行为结论。

## 八、项目中实际积累的 AI 协作开发经验

以下均为本项目真实发生的过程与可核对产物：

1. **人类负责方向与体验验收，AI 负责实现与验证。** PM 提供玩法反馈、优先级和停止/继续决策；AI 完成规则模块、关卡生成、求解器、UI、测试、构建和文档。AI 可以证明「可解」，但不能替代「好玩」的判断。
2. **把规则做成可执行模块，是 AI 协作的关键基础设施。** `src/game-engine.mjs` 与 `tests/experiment-analysis.mjs` 让关卡设计可以用 BFS、顺序穷举和回访指标验证。DEV-006-B 还借助测试发现并修复了 32 位位掩码导致的状态表示问题，改为 BigInt。
3. **「事实 / 判断 / 假设」三分法有效。** `docs/DECISIONS.md`、`docs/playtest-log.md` 与开发日志持续区分真实反馈、产品判断和未验证效果，降低了 AI 把设计假设写成已验证结论的风险。
4. **跨会话交接文档挽救了长任务。** DEV-007 第一会话因上下文超限中断，`docs/DEV-007-HANDOFF.md` 记录了已完成内容、临时产物位置、验证结果和遗留问题，第二会话得以继续而未重做。教训是：长期未提交的工作区仍是风险，应在里程碑处及时归档。
5. **自动化能覆盖「正确性」，覆盖不了「体验」。** 50 关 BFS、UI 回放、响应式布局和持久化都可由脚本验证；但关卡是否有趣、难度曲线是否合理、玩家是否愿意重玩，只能靠人工试玩，且本项目只有产品负责人少量体验。
6. **临时浏览器脚本造成复现缺口。** 多轮 CDP 验证脚本放在系统临时目录、未入库，导致后续无法直接重放全部浏览器证据。未来应在仓库内建立可重复的 Playwright 或等价方案。
7. **生成式关卡生产必须配有强校验。** 40 关由生成器按槽位标准产出，再经合并脚本逐关回放、完整 BFS 和去重检查。没有这些校验，生成规模只会放大不可解或低质量问题。
8. **工程交付规模不等于产品成功。** 50 关、44 项测试、静态发布包都真实完成，但它们证明的是工程完整性，不是核心玩法成立。

## 九、最终决策与后续

### 最终决策（2026-10-24）

1. **停止《方向回声》的主动功能开发。** 不再新增关卡、机制、道具或发布功能。
2. **保留全部现有成果。** 50 关数据、规则模块、关卡求解与生成工具、实验关卡、测试、构建脚本、文档与历史基线均归档，不删除、不重置。
3. **不再以发布为目标修改玩法、UI 或默认首页。** 现有 `dev/` 分支与静态包作为历史证据保留。
4. **转向新的游戏创意探索。** 新方向另立任务与项目，不在本仓库继续扩展。

### 不再执行的事项

- 50 关统一人工试玩验收（PT-007）；
- 根据试玩反馈微调关卡或更换种子重生；
- 仓库内 Playwright 浏览器回归补齐；
- 真实手机 / iOS Safari 验收；
- GitHub 备份、远程 Push、PR 或正式部署；
- favicon 404 等发布细节修复；
- 新关卡、新机制、商业化或后端能力。

### 可复用的资产

- 方向约束规则模块与 BFS/顺序/回访分析工具；
- 关卡生成、合并、去重与证据输出流程；
- 静态打包与敏感信息扫描脚本；
- AI 协作任务拆分、交接文档与「事实/判断」记录规范；
- 本次核心教训：**如果一个机制只在特定路径选择下才生效，必须验证它在最优解和自然解中是否真的不可绕过。**
