# 试玩日志 / Playtest Log

只记录真实发生的试玩、可复现的操作与真实反馈。没有记录的细节标记为“待补充”；不得虚构参与人数、体验数据或复测结论。

## 记录字段

| 字段 | 说明 |
|---|---|
| 版本 | 试玩对应的版本或提交 |
| 关卡 | 关卡编号；整体体验可注明“全九关/未逐关注明” |
| 测试操作 | 实际执行的操作路径或观察方式 |
| 体验问题 | 真实观察到的现象与主观反馈 |
| 严重程度 | 由 PM 评估；无评估时写“待评估” |
| 改进建议 | 可验证的假设或待讨论方向，不写成已定方案 |
| 复测结果 | 复测版本与结论；未复测则写“未复测” |

### PT-003｜DEV-002/DEV-003 实验关卡单次体验反馈

- **版本**：DEV-002 + DEV-003 本地分支 `dev/dev-002-gameplay-experiment`（提交前）
- **关卡**：实验 B「顺序的陷阱」、B1「先远后近」、B2「预留退路」与棋盘 UI
- **测试操作**：用户单次真实体验；具体步数、时长与是否逐关通关**待补充**。
- **体验问题**：
  1. B「顺序的陷阱」：较简单；起始只有两个主要方向，错误方向容易陷入循环，正确方向可以顺利通关。
  2. B1「先远后近」：产生了实际思考乐趣；玩家发现最近收集物无法先拿，通过重新规划，选择先获取较远收集物。
  3. B2「预留退路」：存在设计巧思，但玩家按照自然路线即可通关，未明显感知预留退路的必要性。
  4. UI：玩家站在已有箭头的格子上时，角色模型遮挡箭头，需要修复。
  5. 格子形状、棋盘清爽程度、取消提示后的操作体验及其他视觉辨识度尚未得到明确人工确认，不得标记为人工验收通过。
- **严重程度**：UI 遮挡箭头建议按显示缺陷处理；其余主观体验待 PM 评估。
- **改进建议**：优先修复角色遮挡箭头问题；B2 若要让“预留退路”被感知，可能需要更明确的失败反馈或关卡提示，但需先讨论，不得擅自加机制。
- **复测结果**：未复测。
- **备注**：以上为单次真实用户反馈，不代表普遍玩家体验。

### PT-004｜DEV-004 B1+ 单次体验与 B1/B1+ 机制审计

- **版本**：DEV-004 本地分支 `dev/dev-002-gameplay-experiment`（提交前）
- **关卡**：B1+「先远后近·进阶」；对照 B1「先远后近」
- **测试操作**：用户单次真实体验 B1+；具体步数、时长与撤销次数**待补充**。
- **体验问题**：B1+ 未经策略思考便直接通关，且通关过程中没有重复进入任何格子；与 B1 需要主动推翻“先拿最近收集物”的体验不同，B1+ 的多阶段顺序约束未被玩家感知。
- **机制审计结论**：详见 `docs/DEV-004-REPORT.md` 第 7 节。摘要：B1 与 B1+ 都存在无重复通关路线；B1+ 的 12 步自然走廊路线本身对应可通关收集顺序，而箭头规则只在再次进入旧格时才生效，因此“仅 6/24 收集顺序可通关”的技术约束没有转化为实际决策压力。
- **严重程度**：待 PM 评估。
- **改进建议**：若继续深化 B1+，需要让自然可走路线不再自动满足获胜顺序，或强化“最近收集物”的显性诱饵。该方向需 PM 批准，本轮不擅自改玩法。
- **复测结果**：未复测。
- **备注**：本条为单次真实反馈，不代表普遍玩家体验；机制数据来自实际规则模块的只读穷举，不是玩家统计数据。

### PT-005｜DEV-005-B E1/E2 单次真实体验

- **版本**：DEV-005-B 本地分支 `dev/dev-002-gameplay-experiment`（提交前）
- **关卡**：E1「诱人的近路」、E2「取舍的时机」
- **测试操作**：用户单次真实体验两关；E2 首次通关为 20 步；E1 的具体步数、时长与撤销次数**待补充**。
- **体验问题**：
  1. E1「诱人的近路」：有趣，经历了主动思考和策略调整；需要思考第一个先收集哪个目标，具有一定策略感。
  2. E2「取舍的时机」：有思考，但整体乐趣一般；首次使用 20 步通关，发现游戏提供的目标为 16 步后，产生了优化路线的探索欲望。
  3. 综合评价：玩家认为目前这些关卡整体仍不够好。
- **严重程度**：待 PM 评估；产品决策见 `docs/DECISIONS.md` 2026-10-23 记录。
- **改进建议**：正式版优先吸收 B1、E1 中得到正面反馈的收集顺序策略；保留最短步数挑战作为额外游玩动力。具体方向以 PM 决策为准。
- **复测结果**：未复测。
- **备注**：以上为真实的单人体验反馈，不代表普遍用户结论；UI 人工验收尚未确认，不得标记为通过。
